# 住宅モデル仕様・寸法台帳

[目次](../docs/README.md) · [住宅資料](README.md) · [計算仕様](../docs/calculation.md) · [検証資料](../docs/verification.md)

本書は住宅の座標・形状・採用値の正本とする。資料からの観察、図面の概算、計算用の仮定、未確認の実寸を分ける。現行モデルは `maisonette-assumed-v3`、仮定セットは `A-MAISONETTE-2026-10-07-v3`。**住宅寸法の実測は0件**であり、測量による住宅再現や実際の搬入の保証ではない。

対象は一方向の「玄関 → 階段 → 2階到達後に右折 → 左右に扉のない直線廊下 → LDK入口」。ゴールはマージン箱全体の入口通過で、LDK内部の再現・移動・旋回・設置・姿勢復元、他室への経路は対象外とする。右折と側扉なしは利用者指定で、寸法や写真の実登録を確定した事実とは区別する。

## 台帳の契約

## 座標系と要素の責務

内部単位はm。記録/入力用のmmから変換する入口は共通の単位処理に集約する。Yを鉛直上向き、+Zを玄関の外から室内へ向く法線、+Xを玄関から内側を見た左方向とする右手系を使う（その視点での右方向は−X）。原点は「玄関枠の内側端平面にある有効開口の左右中央、土間基準床面」。有効開口と土間が未確定なので、この定義だけでは原点の住宅実座標が確定したことにならない。

要素ID・表示名のleft/rightは方向判断の基準にしない。たとえば`solid-entry-jamb-left`（表示名「玄関左枠と壁」）は世界X=[−1.385,−.385] mにあり、玄関外から+Zへ向く視点では右側である。左右を記述するときは、その地点の進行方向と世界座標を併記する。

箱の位置は梱包箱中心、ローカルX=幅・Y=高さ・Z=奥行、姿勢は `Pose` の正規化quaternionとする。安全マージン付き箱は同じ中心・姿勢で各軸の寸法に `2s` を加える。姿勢の補間は `interpolatePose` と同じ位置の線形補間・最短回転補間を使う。

| ID種別         | 責務                                            | 例                                     |
| -------------- | ----------------------------------------------- | -------------------------------------- |
| `region-*`     | 基準点が属する経路床領域、床上面高、隣接関係    | `region-doma`、`region-step-001`       |
| `solid-*`      | 厚みを持つ物理形状と、元寸法への参照            | `solid-step-001`、`solid-waist-cap-01` |
| `opening-*`    | 通過方向、枠の両端平面、有効開口形状、扉ID      | `opening-entry`、`opening-ldk`         |
| `portal-*`     | 隣接領域の共有境界と床IDの遷移条件              | `portal-step-001-002`                  |
| `constraint-*` | 持上げ上限、外周包含、開始/終了条件等の仮想制約 | `constraint-lift-step-001`             |

床領域と立体形状は別のデータであり、同じIDを兼用しない。単一踏面が非凸なら複数の凸立体へ分割しても、踏面領域IDと段番号は維持する。画像上の左右や写真の向きは `sourceRegistration` に記録し、住宅座標へ対応づける根拠を残す。未確認の登録変換を単位変換や描画補正に紛れ込ませない。

住宅の各 `modelVersion` は、寸法台帳の版、採用数値/仮定、物理形状と元寸法ID、床グラフとポータル、扉姿勢、持上げ/外周/終端制約、未確認項目一覧をひとつの変更不能なスナップショットへ一意に対応させる。いずれかを変更したらモデル版を更新する。ローカル画像を含めずに、この対応を結果から追跡できることを住宅統合の条件とする。fixtureは別の版と出典を持ち、住宅用の採用値へ流用しない。開始の操作方針には独立した版識別子がないため、住宅形状版v3が同じ結果でも、証拠では開始条件を別に記録する。

## 固定経路の領域・床・開口

次の順序は経路の接続を定める。階段を上り切るまでの段数・各形状・登録位置を表す具体値は未確認。図の並びは実際の左右や縮尺を示さない。

```mermaid
flowchart LR
  S[玄関外の開始領域] --> E[玄関開口]
  E --> D[土間]
  D --> K[框・階段前床]
  K --> L[下側の各直段]
  L --> W[高さの異なる各回り段]
  W --> U[上側の各直段]
  U --> H[2階到着後に右折 → 直線廊下・左右に扉なし]
  H --> O[LDK入口の枠・開放扉]
  O --> G[箱全体の開口通過で終了]
```

| 領域                     | 床/物理形状                        | 接続と開口                | 完了条件への役割                                           |
| ------------------------ | ---------------------------------- | ------------------------- | ---------------------------------------------------------- |
| `region-entry-outside`   | 玄関外床と確認した障害物           | `opening-entry`外側へ接続 | 開始箱全体が玄関枠外側にある                               |
| `region-entry-threshold` | 敷居・枠の局所通過床               | 玄関枠の厚み全体を結ぶ    | 扉を含む有効開口を連続して通過                             |
| `region-doma`            | 土間床、周囲壁/収納                | 敷居→框前面               | 土間の高さを階段前床へ置換しない                           |
| `region-pre-stair`       | 框立体、階段前の水平床             | 框→第1段                  | 玄関直後の水平床として記録                                 |
| `region-step-i`          | 各直段/回り段の凸立体集合          | `i-1`/`i+1`との共有辺だけ | 下側→回り段→上側の全段を通る                               |
| `region-upper-hall`      | 最終段からLDK入口までの廊下床/壁   | 最終段→`opening-ldk`      | 廊下の通過と最終姿勢の候補生成                             |
| `region-ldk-threshold`   | LDK枠の奥行内にある敷居/床、枠、扉 | 廊下側枠端→LDK側枠端      | 入口の厚みを含む通過                                       |
| `region-ldk-receiver`    | 物理的なLDK床を生成しない仮想補助  | LDK側枠端だけ             | 開口の先へ出た箱の部分を終端評価に保持し、全体通過で即終了 |

複数の廊下床多角形が必要な場合も、ひとつの固定経路の構成要素としてIDを分ける。浴室・トイレ・収納・他の洋室へは隣接辺を作らない。後退・横移動による姿勢調整は同じ隣接グラフ上で認めるため、探索内部の各辺を上り方向のみへ制限しない。最終的な経路の開始/終了と対象は固定する。

## 形状生成規則

各床領域は水平XZ多角形 `P_i` と完成床高 `h_i` を持つ。直段は矩形、回り段は資料を数値化した踏面多角形を使い、底面高から `h_i` まで押し出した厚みのある立体を作る。内部を通過可能な空洞にしない。非凸踏面は閉じた凸多角柱へ分割し、その和集合が元の踏面と一致することを面積・境界で検証する。上面だけの三角形メッシュや斜面で代用しない。

段台帳は昇順 `step-001` から付番し、各段に「区分、XZ頂点、上面高、底面高、直前/直後の共有辺、蹴上げ高、出典寸法ID、仮定ID」を持たせる。仮定住宅版は `createMaisonetteModel().stepLedger` の16行と最終段から廊下への蹴上げを正本とする。全蹴上げ高の和は階段前床から2階床までの階高と一致させ、途中の隙間・高さ逆転・同一段への誤った二重付番を拒否する。各段の高さを線形補間して滑らかな斜面にしない。

中央腰壁は壁本体、笠木、必要なら傾斜/段折れした天端を表す複数の立体で生成する。回り段側の端部・上下階側の端部も閉じた面を持たせる。箱の角が笠木へ当たるケース、腰壁に完全包含されるケース、端部へ回転中に当たるケースを検証する。外側手すりの除外は中央腰壁の除外を意味しない。

外壁・間仕切りは通路内面を正本として開口部分を抜き、到達し得る探索高さ全体を覆う。天井が高いという仮定によって壁の上へ抜ける経路を作らない。壁の上端を実測していない場合、探索高さまで延長するモデル上の仮定を記録する。到達可能な箱の上面より通路側壁上端を高くし、その生成上端へ乗り越える候補を許可しない。上階廊下と交差する下階壁の人工延長は上階床下面で止め、上階の物理床と側壁を別に置く。玄関の要素`solid-entry-jamb-left`は上階床と重ならず、探索高さまで延長して枠上方の迂回を防ぐ。開口の上枠・敷居・扉は天井とは別の物理形状として残す。

扉は開放状態を固定した厚みのある障害物とする。蝶番軸、扉幅/高さ/厚み、角度、開放先側を台帳へ記録し、開口の最狭部と整合させる。探索中の扉の開閉・取り外し・ドアストッパー移動は扱わない。LDK入口の開放扉がLDK側に張り出す場合も、その扉立体は入口の一部としてモデル化する。室内を作らないことを理由に扉を消さない。

## 床所属・持上げ・連続遷移

探索状態は `Pose` に加えて床領域IDを保持する。基準点は箱中心のXZ投影 `a=(p.x,p.z)`。通常状態では `a ∈ P_i` とし、梱包箱の最下点を `b(p,q)=p.y-halfExtents(packed,q).y`、局所持上げ量を `l_i=b-h_i` と定義する。持上げ上限 `L_i` は計算上の制約であり、搬送能力・天井高の実測値ではない。

1. 通常領域では各面の安全マージンを `s` として `s ≤ l_i ≤ L_i` を要求する。物理衝突は常に回転後のマージン付き箱で別に検査するため、この不等式だけで床からの安全距離が確保されたとはしない。
2. 領域IDを変えられるのは隣接表に登録した `portal-i-j` の共有線分上を基準点が通過したときだけ。段を飛び越えたり、最も都合のよい近傍床を選び直したりしない。
3. 境界点では両床の条件を同時に満たす。すなわち `max(h_i,h_j)+s ≤ b ≤ min(h_i+L_i,h_j+L_j)`。さらにその点と前後の全区間で、マージン箱と高い側の蹴上げ/踏面も衝突しないことを検証する。旧床の上限を先に外して新床へ切り替える処理は不可。
4. 同じ階の隣接する床多角形の内部は重ならず、共有境界だけを重複所属として許す。土間と2階廊下のように別階でXZ投影が重なる場合は、状態に保持した床IDと登録済みポータルから遷移先を選ぶ。投影が重なるだけで他階へ飛ばない。数値的な位置誤差帯は床幅を増やす許可領域ではない。境界にあること・前後の側・共有線分内であることを誤差内で判断できなければ未検証とする。
5. 姿勢間の連続検証ではポータル横断点で区間を分け、各開区間の床IDと境界の両条件を再検証する。一定間隔のサンプルだけで細い段や領域外への逸脱を見逃さない。短縮後も同じ規則を再適用する。

箱全体を各踏面の垂直投影内へ閉じ込めると、複数段をまたぐ搬送や中央腰壁上への部分的な張出しを誤って禁止する。このため各踏面の所属は中心投影で決め、箱全体については物理衝突と経路外周の包含制約を別に適用する。外周の許可集合は踏面 `P_i` の和集合とは別の三次元制約データとして定義し、住宅台帳の登録位置・外周境界・許可高さとともに確定する。中央腰壁の平面位置にある穴をそのまま箱全体の禁止柱へ押し出さず、腰壁上への部分的な張出しを含められる外周集合と、腰壁の実形状を使う。外周へのはみ出しは許可しない。中央腰壁上への箱の一部の張出しは実形状に従って評価するが、中心が腰壁を横切って反対側の階段へ移る遷移は作らない。

`region-ldk-receiver`だけは未再現室内へ入る終端補助であり、物理床が確認された通常床領域とは異なる。持上げの基準はLDK側枠端の床高を延長した仮想基準と明記し、この延長面を物理すき間へ混ぜない。室内側の床段差や障害物は評価していないことを結果の適用範囲に残す。

## 開始とLDK入口ゴール

開始は玄関外の対象操作領域内とし、利用者指定により、荷物中心を玄関枠の外側端平面から外方向1mに固定する。現行の法線+Zと外側面Z=−.145mでは中心Z=−1.145mとなる。横方向・回転・傾斜・持上げは候補を検査し、マージン箱全体が開始領域の外周制約に収まり、玄関枠外側にあり、割り当てた床と持上げ条件を満たす場合だけ採用する。1m地点で収まらない姿勢を玄関直前へ移して開始しない。外部開始領域から玄関へ進む辺は、室内向き法線への中心投影が減る場合に拒否する。回り段などの後続区間の後退・姿勢操作は引き続き探索する。戸枠内に最初から箱の半分を置く候補は開始にしない。製品固有の搬送姿勢制限は対象外であり、直立へ必ず戻す条件は加えない。開始位置の正本は[共有開始基準](../src/model/entry-start.ts)で、未計算時の表示と探索が共用する。中心を基準にする理由は、箱前面を基準にすると寸法・姿勢で開始中心が変わるためである。これは外部空地の実測ではない。

単位法線 `n` に対する支持幅は `support(d,q,n) = Σ_{k=X,Y,Z} (d_k/2) × |n·R(q)e_k|` とする。`d`は箱の各軸寸法、`e_k`はローカル単位軸、`R(q)`はquaternionによる回転であり、原点中心の回転後の箱が法線方向へ占める半幅を表す。軸に平行な外接箱の `halfExtents` と `n` の単純な内積ではない。玄関の室内向き法線を `n_entry`、外側枠端平面を `n_entry·x=c_entry_outer` とすれば、開始の箱全体の外側条件は `n_entry·p + support(clearance,q,n_entry) ≤ c_entry_outer − εterminal` とする。

非凸な開始領域・外周制約では、箱の8頂点だけが内部にあることを全体包含の証明にしない。箱と領域外の交差、または同等に保守的な分解で箱全体の包含を検証する。

LDK入口には廊下からLDKへ向く単位法線 `n`、廊下側枠端の平面 `n·x=c_in`、LDK側枠端の平面 `n·x=c_out`（`c_out ≥ c_in`）、有効開口の横方向/高さ、枠と開放扉の物理形状を登録する。法線と平面は開口の実配置に由来し、図の画面左右から即決しない。

終了は次をすべて満たす最初の姿勢とする。

- 同じ連続経路が玄関外の開始から全床領域と `opening-ldk` を通っている。
- マージン箱の全頂点 `v` について `n·v ≥ c_out + εterminal`。同値な支持幅表現では `n·p - support(clearance,q,n) ≥ c_out + εterminal`。中心点のみの通過は不十分。
- 開口の厚み全体・固定扉・廊下壁・確認した敷居/床との非衝突と、所属/持上げ制約を最終区間まで検証済み。
- 通過後の姿勢復元・室内旋回・設置へ経路を延長せず、通過イベントで終了する。

`εterminal`は境界位置の計算用の正の通過しろで、実測誤差や利用者の安全マージンとは別に記録する。仮定住宅版では1.5 mmを `A-LIMITS` として採用した。凸形状全般の演算誤差を証明する値ではない。開始の外側判定にも同じしろを使う。

LDK室内を再現せず全体通過を判定するため、入力箱に合わせた有限の仮想受け領域を生成する。初期の終端候補生成では、マージン箱全体を廊下側枠端より手前に置ける候補姿勢 `q` を作り、姿勢と開口面内の位置を保って `+n` に平行移動する最終区間を検査する。受け領域はその区間で `n·x ≥ c_out` に出る箱の掃引部分だけとし、法線方向の奥行上限は `2 support(clearance,q,n) + εterminal`。室内での追加の旋回に使える自由な部屋は生成しない。

この候補生成は開口通過を単純に検証する初期方式であり、通過中の回転が必要な実際の搬送を網羅しない。候補が得られない/候補が衝突した場合は探索条件内の未発見とし、LDK入口が絶対に通らないと断定しない。候補生成法を後に広げる場合も、LDK室内が未評価であることと、全体通過で終了する境界を維持する。

仮想受け領域はLDK側の空間がその範囲だけ空いているという計算上の前提であり、室内の存在する物・床・壁を検証した証拠ではない。結果には「LDK入口の箱全体通過まで。室内の障害物・移動・設置は未評価」と適用範囲を保持する。開始側は対象住宅への進入を評価するため、同じ仮想受け領域で代用しない。

## 主表示のすき間

主表示は**「梱包箱と住宅形状の最小すき間」**とする。マージンを加える前の梱包箱表面から、評価した経路上の物理形状の和集合までの距離を対象にする。外壁、間仕切り、玄関/LDK枠、固定扉、床、敷居、框、各踏面・蹴上げ、中央腰壁・笠木を含む。天井、除外した手すり等、未再現LDK室内は含まない。

通過可否の確認はマージン付き箱の衝突照会で行い、主表示用の距離照会と混同しない。必要に応じてマージン付き箱からの残り距離を「マージン外側の余剰」と別に保持できるが、主表示の値として返さない。箱の各面に加えた直方体マージンは球状膨張ではないため、梱包箱の距離から単に `s` を引いて余剰を作らない。

`constraint-*`、ポータル、仮想持上げ上限、仮想受け領域、外周の人工境界は物理すき間の最寄り障害物にしない。物理障害物ID集合と仮想制約違反ID集合を異なる結果欄に保持し、仮想違反に最寄り障害物や物理距離を付けない。物理障害物と有効経路が同じなら、仮想境界だけを広げてもすき間と物理障害物IDは変わらないことをテストする。LDK側へ出た部分は室内障害物を評価していないため、この値を室内のすき間へ拡張しない。

値は経路全体に対する区間推定とし、数値誤差、区間の位置、物理障害物ID、未評価範囲を伴わせる。住宅寸法の推定誤差を数値計算誤差0.25 mmなどに含めたことにはしない。未計算は `null` 相当を維持し、0・無限大・安全と読み替えない。製品は独立f64の物理照会を使い、モデル照会は物理距離と仮想制約を分離する。[計算仕様](../docs/calculation.md)を参照する。

## 現行モデルの採用値

実装の正本は[住宅形状](../src/model/maisonette-model.ts)、採用理由・出典・D-IDとの対応は[採用台帳](../src/model/maisonette-assumptions.ts)とする。全必須寸法には個別の仮定を割り当て、`certainty: assumed`、`uncertainty: unknown`、`measurementCount: 0`を保持する。各物理要素の`elements`が仮定IDを参照し、段ごとの頂点・高さ・共有辺を`stepLedger`と`geometry.portals`に保存する。資料の概算値・未確認欄を上書きしない。

### 採用理由

- 二列の直段、扇形踏面、腰壁・笠木、土間・框を保持する。推定通行幅780 mm×2と折返し1600 mmの差から壁厚を逆算せず、770×2＋110 mmの整合する仮定セットを採用する。
- 計算と3Dは同じ形状を使い、描画だけの鏡像・位置補正を加えない。上側直段の進行は−Zで、その地点の右が+Xとなるため、到着床から+Xへ曲がる。
- 上階廊下と交差する下階壁は人工延長を上階床下面で止める。玄関の要素`solid-entry-jamb-left`の上方は上階床と重ならないので延長で塞ぐ。低い上端だけでは傾斜した長物が枠上方の余剰空間を使う負例がある。上階の変更時も下階の持上げ・頭上干渉を全区間再検証する。
- 床・開口・仮想制約と探索候補を分ける。guideは床内の補助点であり、必須通過点や確認済み経路ではない。

### 構造と開始・終端

モデルは63物理solid、物理床28領域と仮想終端1領域、28portal、25guideを持つ。玄関外の横側床・土間の横側床・廊下の補完三角形は同じ操作空間の一部で、全領域を必須チェックポイントにしない。下階と上階でXZ投影が重なる領域も床IDを分ける。

階段中心を基準に組んだ局所Xから.440 mを引き、玄関内側枠中央を原点とする。`opening-entry`は法線+Z、進入平面−.145/退出平面0。`opening-ldk`は法線+X、進入平面1.045/退出平面1.165（いずれも`normal·position`）。LDK前後判定を別階の床へ一律に適用しない。

開始領域は屋外2床で分割した凸矩形で、回転後のマージン箱全体のXZ投影を検査する。中心だけの収まりやモデル全体の広い人工外周で代用しない。将来非凸の開始床へ変える場合は矩形の証明を再確認し、必要なら和集合への全体包含検査へ変更する。初期の後退禁止は候補接続と最終全辺再検証の両方へ適用し、表示経路の切り詰めや未検証区間の追加で補わない。

`region-ldk-receiver`は`basis: terminal-reference` / `physicalSolidId: null`である。9.010 m全体を自由な部屋として使わず、選んだ姿勢・横位置を保つ+X方向の最終掃引部分だけを許す。箱全体が退出平面＋.0015を越えたところで終了する。
