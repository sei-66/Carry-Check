# 計算仕様

[技術構成](architecture.md) · [住宅モデル仕様・寸法台帳](../references/housing-model-spec.md) · [検証記録](verification.md) · [幾何検証](geometry-verification.md)

## 対象と結果の意味

対象は固定した一方向の「玄関 → 階段 → 2階廊下 → LDK入口」である。現行の住宅版は `maisonette-assumed-v3`、仮定セットは `A-MAISONETTE-2026-10-07-v3`。階段を上がった後に右折し、側扉のない直線廊下を進む。荷物中心は玄関枠外側面の1 m手前から始まり、玄関へ入る初期区間の中心後退を認めない。終端は、マージン箱全体がLDK入口の枠の離脱面を越えた位置とする。枠を抜ける最後の移動では姿勢と横位置を保つ。LDK内部の形状、室内移動、設置姿勢は評価しない。座標系、寸法と出典、開始・終端面の数値は[住宅台帳](../references/housing-model-spec.md)を正本とする。

利用者は梱包材を含む外寸と各面の安全マージンを入力する。幅・高さ・奥行の内部軸はX・Y・Z、Yは上向きで、内部の長さはm、入力はmmである。入力の各辺は1〜5000 mm、マージンは各面5〜100 mmとし、検証後に一度だけmへ変換する。梱包箱と、各辺を `2s` 拡張した判定用マージン箱は別の形状として扱う。位置は両箱に共通の幾何中心で、回転は検証後に正規化したquaternionで表す。`q`と`-q`は同じ姿勢である。位置の線形補間と最短弧の球面線形補間を計算・最終再検証・再生で共用する。

結果の「経路確認」は、版付き仮定住宅、入力、持上げと探索制約の下で、開始から終端までの全移動区間を連続検証したことを意味する。有限候補の未発見、時間・ノード・照会上限、未検証区間は実住宅での搬入不可の証明ではない。入力・モデル不備と中止・処理失敗も区別する。実測住宅寸法は0件であり、仮定モデルの機能完成を実住宅への適合、対象実機での性能、公開の合格へ読み替えない。完了済みと未確認の検証は[検証記録](verification.md)を正本とする。

## 住宅モデルと責務

`src/model/`は物理solid、床領域ID、登録portal、開口と法線、候補guide、持上げと人工外周、開始・終端領域を作る。3D表示は同じ物理solidを使い、見通し用に切り欠いた壁が計算形状と異なることを明示する。直段、6つの回り段、中央腰壁と笠木、床、枠、固定した開放扉を厚みのある形状として扱う。回り段を平らな踊り場や一枚の斜面へ置き換えない。上階形状の変更は下階の頭上干渉にも影響するため、変更時は全経路を再検証する。

図面の概算値、画像から観察した形状、計算用の採用仮定、実測値を区別する。未確認値を0や任意の既定値へ黙って置換しない。モデル版は採用台帳、形状、床グラフ、扉姿勢、持上げ・外周・終端制約に対応し、これらの変更時に更新する。旧版の経路と時間は新版の実績へ流用しない。元の住宅画像はローカル資料であり製品資材に含めない。詳しい出典・確度と残る実測ゲートは[住宅台帳](../references/housing-model-spec.md)に置く。

床所属の基準は箱中心である。一方、物理衝突、開始領域への収まり、人工外周、終端通過には回転後のマージン箱全体を使う。XZが重なる積層床を近傍だけで選ばず、中心線分が共有辺を横断する全時刻を求め、各開区間の床所属を検査する。床IDを変更できるのは登録portalだけで、横断点は旧床と新床の両方の持上げ条件を満たす必要がある。境界に沿う曖昧な移動、非隣接床への飛越、数値的に区別できない横断は未検証とする。持上げは梱包箱の最下点と所属床高との差であり、天井高さや作業員の能力を示す実測値ではない。物理衝突、床・portal、持上げ、人工外周はそれぞれ独立に証明する。

仮想のLDK受け領域は開口を抜ける終端の直進検証を受け止めるための領域で、物理床でも室内の自由空間でもない。guideは候補生成の補助点で、訪問義務や通過の証拠ではない。guideを飛ばす辺も、途中で横断するすべての床・portalと箱全体の物理衝突を連続検証する。

## 距離と連続移動の証明

製品の物理照会は独立したf64幾何区間で行う。`physical-query.ts`は梱包箱とマージン箱を物理solidへ別々に照会する。凸多角柱と回転箱の面法線および辺の外積軸で得る正の投影離隔を距離下限とし、頂点対面・辺対辺を含む有効な点対の距離を上限とする。候補点対の距離を下限に転用しない。有限線分は端点射影を必ず含め、条件のよい内点候補を加える。近平行などで真の最短点を特定できなくても、上限である性質を保つ。下限・上限を数値誤差ぶん外側へ広げ、矛盾した区間や非有限値は照会失敗とする。正の下限が証明された場合だけ離隔を確定し、誤差をまたぐ状態、照会失敗、分割上限は通過としない。±0.25 mmは検証した局所・合成条件の暫定誤差予算で、任意の住宅形状の保証値ではない。

Rapier 0.21.0はM1比較診断に限定する。回り段局所形状と傾けた50 mm箱の解析上0.1 mmのすき間で、1 mの照会範囲内にもかかわらずRapierが`null`を返した。旧合成アダプターの`null → 予測範囲に基づく下限`を住宅へ流用すると危険な過大下限になるため、Rapierの返値、形状未生成、診断失敗は通過証明に使わない。比較診断は明示的にfactoryを注入したM1専用経路で実行し、未実行と不一致なしを区別する。固定raw APIの資源所有権・contact結果の形式は依存更新時に再確認する。局所プローブの条件、診断失敗の分類と実行済み結果は[幾何検証](geometry-verification.md)に記録する。

移動区間は中心位置を線形補間し、姿勢を最短弧で補間する。許容ノルム誤差内のquaternionも正規化し、相対quaternionと`atan2`で微小回転角を保つ。区間内の任意点の移動は中心移動量 `t` とマージン箱の外接半径 `r`、最短回転角 `θ` による `t + 2r sin(θ/2)` で包める。物理形状については全掃引の保守的な支持平面下限で証明できる区間を先に処理し、証明できなければ距離下限と適応分割へ進む。持上げは中心Yの線形範囲と回転後の縦支持幅を別に包む。掃引照会も共有予算へ数える。端点のみの非衝突や一定間隔のサンプルから途中の通過を推定しない。

`model-query.ts`は物理距離と床・持上げ・人工外周の制約を別欄に持つ。人工外周や仮想受け領域は物理障害物のIDや距離へ混ぜない。実形状として生成した床・壁・枠・扉・腰壁は物理距離の対象とする。同じ物理solidと有効経路なら、人工境界だけの変更で報告する物理距離は変わらない。

## 探索と予算

`maisonette-search.ts`は位置、回転、床IDを状態に持ち、guideの候補層と連続検証済みの辺から有向経路を探す。開始中心は玄関枠外側面の1 m手前に固定し、屋外開始領域にマージン箱全体が収まる候補を検査する。終端候補はマージン箱の支持幅から作る。代表の1姿勢が不適合でも領域全体の配置不能と結論しない。候補の不適合、予算内での候補未発見、有効候補間の経路未発見、モデル不備を分ける。

同床内の局所接続は、壁と回転後の箱支持幅から位置、持上げ、複合回転の候補を作る。開口に適合する静止姿勢だけでは次の姿勢までの接続を保証しないため、前半・局所接続・後半のすべての辺を同じ幾何検証で確認する。局所候補の配分はマージン箱3辺の中央値と狭い開口幅の比から決めるヒューリスティックで、通過条件ではない。固定参照へ1〜20%、局所接続へ追加5〜60%を配分し、製品の5000ノード条件では通常探索へ最低1000ノードを残す。比率0.5未満では局所枠を使わない。特定製品の参照座標や成功経路を製品へ埋め込まない。

製品の既定値はseed `20260930`、5000ノード、15秒である。通信契約が許す上限は20,000ノード・30秒、探索全体の照会上限は50,000件。候補生成・姿勢照会・辺検証・最終全辺再検証・経路すき間評価は同じ時間と照会予算を消費する。打切りや例外、未確定区間を成功へ変換しない。探索中の照会キャッシュで最終再検証を省略しない。参照姿勢列の独立した全辺検証と、入力からの自動発見は別に試験する。途中portalを取り除く、回転途中だけ衝突する、領域から一部が突出する負例も維持する。

## 経路すき間と通信

主すき間は確認済み経路全体での、元の梱包箱表面と物理solidの最小距離区間である。マージン箱による通過条件とは別で、マージンを差し引いて元の距離を推定しない。`path-clearance.ts`は全掃引を包む距離下限と実サンプルによる上限を適応的に狭める。内部の区間幅を0.8 mm以下にし、画面では両端を0.1 mm単位で外向きに丸めても1 mm以内に収める。予算内に完了しない場合は`clearance: null`とし、0 mmや十分な余裕を意味させない。代表位置は上限を与えた実サンプルの姿勢であり、厳密な最小点ではない。経路全体で最寄りsolidが確定しない場合の`obstacleId`は`null`にする。

固定ルートID・方向・モデル版と入力snapshotを要求と応答で照合し、未知の床・物理ID、不正な姿勢、代表姿勢と補間位置の不一致を拒否する。Workerの`ready`は通信起動でありモデル準備完了ではない。通信起動20秒、エンジン初期化30秒、計算は要求時間+1秒（最大31秒）、Worker世代寿命70秒を独立に管理する。進捗は期限を延長せず、応答受信時にも絶対時刻を確認する。中止、入力変更、失敗、期限到達、完了時はWorkerを終了し、次の要求で作り直す。同期計算中の`cancel`メッセージだけには依存しない。段階別期限と古い通知の拒否は`application/`が管理し、Reactフックで重複実装しない。

## 検証と残るゲート

計算の正例は解析可能な形状や探索器から独立した姿勢列で定め、その全辺を独立に検証してから入力による自動発見を確認する。衝突・包含・薄い障害物・微小回転、数値誤差、床・portalの飛越、開始領域からの後退、終端での箱全体の通過、仮想境界と物理すき間の分離、期限・中止・再生成を回帰に含める。処理の正常終了、経路確認、すき間評価を別々に数える。性能は製品資材と実Workerの同一条件で比較し、入力、モデル版、開始条件、予算、端末、キャッシュ、試行回数を記録する。

実住宅の寸法・扉位置と資料画像の登録、住宅用形状全般の数値誤差根拠、iOS SafariとAndroid Chromeでの初回・後続計測、実メモリとGPUの保持、読み上げ、公開範囲は残る確認である。計測入口の成功やPCでの単発値をこれらの合格としない。製品コードにM1専用入口、合成fixture、表示専用廊下を接続しない。検証の手順と実績は[検証記録](verification.md)・[性能記録](performance.md)に置く。
