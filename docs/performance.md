# 性能計測とレビュー

[README](../README.md) · [開発ガイド](development.md) · [検証記録](verification.md) · [計算仕様](calculation.md) · [幾何検証](geometry-verification.md) · [住宅モデル仕様・寸法台帳](../references/housing-model-spec.md)

本書は製品Workerと3D表示に関する2026-10-04の性能測定をまとめる。計算と表示の計測入口は製品ビルドから分離し、製品と同じ`CalculationClient`、Worker、`createRouteViewer`を使った。速度のために幾何の証明、数値誤差、最終全区間検証、期限・中止の契約は緩めていない。

## Worker計算と製品資材

初回画面の単発観察は変更前FCP 164 ms、canvas要素の準備273.9 ms、改善後FCP 100 ms、canvas準備225.5 msで、どちらもlong task検出は0件だった。canvas準備は描画完了や冷間ロードを測った値ではない。キャッシュと描画タイミングを制御していない単発値から初期表示の短縮は主張しない。

## 画面外表示、更新、描画

追加測定はWindows / Chrome 154のlocalhost本番プレビューで行った。通信・CPU制限とキャッシュの強制消去はなし。最初の描画試料はDPR 1.5、その後の比較はviewport指定でDPR約1.0。390×844はデスクトップブラウザ上のviewport検査で、スマートフォン実機ではない。

| 接近前のcanvas数 / 描画JS要求                    | 1 / あり | 0 / なし |
| 計算中の静止canvas・2秒間の描画呼び出し          |      468 |        0 |

| 再生中のRAF平均                                  | 約60 fps | 約60 fps |

初期に要求したJS/CSSは約60%減った。これはHTML、ヘッダー、gzip転送量、FCP、GPU完了時間の値ではない。接近後に描画資材を読み込むスクロールからcanvas準備までの観察は113 msの単発値である。暖機後のresource sizeが0になる項目はあり、資材未要求や容量0とは解釈しない。390×844ではviewerが表示領域から約1428 px離れている間に描画JS要求とcanvas生成をせず、表示領域の約160 px以内で一度だけ初期化する条件を確認した。初期から見えるPCでは自動表示する。一度始めたimportは完了させ、そのviewerを保持する。

計算中の描画観察は、実際の製品iframeで600×800×1200 mm・margin 10 mmの探索を始め、カメラと荷物を動かさずWebGL2のdrawElements / drawArraysを2秒間数えた。468回はこの試料の3描画による値で、全入力共通の回数ではない。観察後の中止と入力保持も確認した。不透明材質ごとに静的Meshを結合して描画呼び出しを26.1%減らし、頂点・法線・index・三角形数を維持した。透明壁・扉・輪郭は描画順を保つため個別のままにした。表示CPU時間は中央値0.4→0.3 ms、p95 0.6→0.5 msだったが、単発差から一般的な速度向上率は主張しない。

追加レビューでは、Workerの進捗更新が同じ寸法・経路なしの内容を作り直して静止viewerを再評価していたため、親側のmemo依存を結果参照/nullに絞り、`PreviewPanel`をmemo化した。進捗はplannerの32ノード単位とWorkerの100 ms制限に依存し、常に10 Hzとは限らない。経過時間の0.1秒刻み更新は残す。未使用の`tw-animate-css` importと不要な生成CSSの`@property`定義を除去し、spin・動き低減対応と依存・lockは維持した。Worker通信・返値guard・structured clone・経路区間走査は計測した経路長で有意な費用の根拠がなく、候補順位のsortで距離・回転metricを再計算する点もprofileで支配的と確認するまで低優先とした。結果guard、Worker再利用、候補省略、最終検証のキャッシュ化は採用していない。

## 判定の正しさと残る制約

変更では、判定に使わないRapier診断を製品Workerの物理照会から分離し、Rapier/WASMの生成・照会をM1専用の診断factoryへ移した。製品既定では診断を無効にし、M1入口だけがfactoryを明示する。製品の距離区間と通過判定は独立したf64幾何計算が決める。診断がない、失敗した、または例外になった場合にその結果を製品判定へ転用しない。Node CPU profileで`prismDistanceBounds`、`projectionGap`、`prismSeparation`が上位となった75 solidのホットパスでは投影min/maxを逐次集計し、同じ計算内のprojection frameを共有したが、判定軸や候補を省いていない。

距離区間・物理ID・判定状態が診断の有無で変わらないこと、解析距離、薄い三角柱、近平行辺、輪郭逆順、±15 m移動、微小すき間を回帰条件とした。探索・最終再検証・すき間評価が共有する期限と照会予算を維持し、最終全辺再検証をキャッシュで省略しない。製品画面ではoptionalの`onFrame`がない限り描画診断を採取しない。

記録された条件で`npm run check`は216件のテスト、Lint、整形、型検査、本番ビルドを通過した。通常URLとPages用の製品画面では中止後の再実行、経路・すき間・代表姿勢、B/D切替時の状態保持を確認した。通常製品で1000×300×200 mmの計算は0.52秒、Pagesの小画面では0.51秒で、すき間113.7〜114.6 mmを表示した。初期canvas 0個から有効入力後1個となり、最新寸法と結果を反映した。代表位置42%で停止、ダークモード、上面視点も確認した。Worker契約検証はPASS（各21生成・21終了）、M1計測は`passed`（各35生成・35終了）で、通常/Pages両方の画面を確認し、8画面の警告・エラーログは空だった。StrictModeの20回の生成・解放はすべてcanvas 0→2（廊下と製品）で安定したが、保持メモリの測定ではない。M1の幾何条件と限界は[幾何検証](geometry-verification.md)を参照する。

独立レビューでは、遅延初期化の一度だけの起動、途中unmount時のactive確認、最新props反映、既存のcontext-loss後retry責務、不透明形状の材質別結合と透明形状の描画順を再確認し、重大な未解消指摘はなかった。故意のWebGL context loss後の再試行は実行せず、コード上の確認に限る。M1の`precisionProbe`で`diagnosticsEnabled: true`を維持し、Rapierの微小すき間不一致を記録する条件も確認済みである。

iOS Safari / Android Chrome実機、低速回線、実際のGitHub Pages、GPU時間・保持メモリ、CPU制限下の中止応答、キャッシュを制御した冷間ロードは未確認である。性能目標の開始・中止応答200 ms以内、成立ケース10秒以内、中止後1秒以内に再実行可能、再生・操作30 fps以上は、これらの単発PC測定で実機ゲートを合格にしない。

実機の本番ビルドでは、初期化・中止・再実行を20回繰り返し、Worker・描画リソースの増え続ける保持やクラッシュがないことを確認する。メモリを観測できない端末では測定限界を明記し、確認した挙動と区別する。既存のcanvas数やWorker生成・終了数の記録は、保持メモリの測定を代替しない。この反復検証も未確認の受け入れ条件である。
