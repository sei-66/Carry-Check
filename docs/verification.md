### 日本語の改行

デスクトップのChromium内蔵ブラウザで、ポップ（B）とソリッド（D）の見出し・本文・入力エラー・結果・再生ラベルを確認した。通常文字サイズはviewport幅320・375・768・1280 px、文字拡大は利用者指定の150%までを対象とし、320・375 pxでルートのrem基準を150%にした。

- 通常のAppは両デザイン計12条件で、ヘッダーと本文の横はみ出しがないことをDOM境界と画面で確認した。梱包図の説明は「梱包材を含む」「外寸」の2行、数値と単位、経路名、引用した操作名、短い語句のまとまりを確認した。
- 実際の結果部品を使う一時fixtureで、未入力・処理中・中止・入力不正・各失敗理由・経路成功・すき間未評価など17状態を両デザイン計204条件で確認した。この範囲では、結果見出しの末尾1文字だけが次行に残る状態はなかった。fixtureの時間・距離は表示確認用の値で、搬入の実績には加えない。
- 320 px・150%では、両デザインの4入力欄の範囲エラー、小箱120×180×140 mm・各面10 mmの実Worker結果と再生ラベルを確認した。合成したcontext lossイベントで3Dエラーの文章も確認したが、GPU障害の再現や復旧操作の検証ではない。

補助記録は非追跡の`cache/copy-audit-{states,product,errors,real-result,viewer-error}.json`、確認用ソースは`cache/copy-audit-fixture.html`・`cache/copy-audit-fixture.tsx`、画面は`cache/japanese-wrapping-final-pop.png`。製品入口へfixtureを追加していない。ブラウザ本来のズーム、実機iOS Safari/Android Chrome、OSの文字・動き低減設定は今回の確認に含まない。改行位置はブラウザの文節判定やフォントにも依存する。

### 失敗時と動き低減の模擬検証

Windows / Chromium 155、現行v3・1m開始のPagesサブパス用製品資材が対象。非追跡のローカルハーネスで製品スクリプトの前に障害や設定を注入した。OSの権限拒否やGPU故障そのものを再現した証拠ではない。

| 条件             | 確認済みの範囲                                                                    | 未確認・限界               |
| ---------------- | --------------------------------------------------------------------------------- | -------------------------- |
| 保存拒否・不正値 | 起動、既定値への復帰、保存拒否下の外観変更と計算成功                              | OS由来の拒否条件全体       |
| Worker生成失敗   | 初回constructorの例外を案内し、入力を保持。「計算を再試行」で成功                 | 固定CPU負荷中の中断遅延    |

## 動作確認

[開発ガイド](development.md#セットアップ)に従って起動します。対象は仮定住宅の一方向の「玄関 → 階段 → 2階廊下 → LDK入口」。実測0件でLDK内部は対象外です。以下は現行機能の確認手順です。実施済みの範囲と未確認事項は本書の検証範囲を参照してください。

1. 固定経路・仮定モデル・実測0件・LDK入口までの説明、外寸空欄、各面10mmを確認します。例の選択・逆方向指定がないことも確認します。
2. 120×180×140mm、margin10を入力し「経路を探す」を実行します。実Workerから確認済み経路が返り、住宅3Dで再生/停止/位置指定できることを確認します。1000×300×200mm、margin10は立てた姿勢の検証入力です。すき間は経路全体の梱包面と物理solidの距離区間か、評価未完了と表示します。「すき間の代表位置を見る」の静止表示は厳密な最小位置とは区別します。未発見・上限・期限を不可と断定しないことも確認します。成功・未発見のどちらも結果欄に梱包寸法の再表示や「計算した寸法と条件」の展開操作がないことを通常/開発画面のB/Dで確認します。
3. 幅を空欄・0・5001などにして送信し、欄ごとのエラーと最初の不正欄へのフォーカスを確認します。安全マージンは各面5〜100mmで、0・4.99・100.01mmを拒否し、5・5.5・100mmを受け付けることを確認します。修正後の送信と、入力変更で前の通知が無効になることを確認します。
4. 探索中の中止→同条件再実行、入力変更、連打、再マウントで古い結果/経路が戻らないことを確認します。フォームの中止をクリックとEnterで操作し、中止後に計算が再開しないこと、探索中に入力欄でEnterを押しても再送信しないことも確認します。Worker境界と20回再生成は`/tests/browser/calculation.html`でも確認します。
5. 住宅solidの切欠き表示と計算形状の違い、梱包箱と確認した経路の表示を確認します。経路は常に表示され、安全マージンの3D枠・凡例と両者の表示切替がないことを確認します。安全マージンの入力と計算への適用は維持します。開発専用`/tests/browser/design.html`の一直線廊下は表示専用で、経路選択肢にしません。
6. 通常画面と開発用廊下で、操作開始ボタンを押さずにドラッグ・ホイール/ピンチを試します。操作開始・終了の切替ボタンがなく、canvasの`touch-action`が常に`none`であること、3D表示の外でページを縦スクロールできることを確認します。視点プリセット・拡大/縮小もボタンから操作します。初期表示・視点プリセット・視点リセットは、従来の全体表示から「拡大」1回分（カメラ距離82%）の状態になることを確認します。画面サイズ変更とB/D・表示テーマ切替で現在の拡大率を保持することも確認します。
7. キーボードだけで入力・送信・視点変更へ到達し、フォーカスが見えることを確認します。ライト/ダーク、OS設定追従、動き低減設定も確認します。
8. PC、中間幅、320 × 640、375 × 812、812 × 375、ブラウザ/OSの文字サイズ設定（150%まで）で横スクロールや操作の重なりがないことを確認します。日本語の禁則、語句の途中や文末1文字だけの折り返し、数値と単位の分離も確認します。`npm run build` → `npm run preview`、Pagesサブパスでも一連操作を確認します。
9. B/Dを切り替え、入力・エラー・結果・視点・再生位置を保持しcanvasが増えず、ドラッグ操作が引き続き使えることを確認します。ライト/ダーク/自動は独立して保存します。開発廊下も外観へ連動します。保存値不正・保存拒否は実行確認とコード確認を分けます。

3D表示には WebGL 2 が必要です。ブラウザや GPU の制限で使えない場合は表示失敗を案内し、入力・計算・文字の結果を確認できます。

Pages 配下の資材読み込みは、[Pages 用ビルドの手順](development.md#ci-と-github-pages)でも確認します。計算ロジックの自動テストは[テストの方針](../tests/README.md)を参照してください。

## スマートフォンでの確認

同一 LAN 上の開発 PC で `npm run dev -- --host 0.0.0.0` を起動し、端末から `http://<開発PCのLANアドレス>:5173/` にアクセスします。必要に応じて OS のファイアウォール設定を確認してください。通常の起動はローカル端末だけに公開します。

実際のiOS Safari/Android Chromeで寸法入力・探索・結果・再生・3Dタッチ操作・縦横表示・性能を確認します。画面サイズ指定のデスクトップ確認と実機を区別します。

LAN 公開時も、[住宅資料の扱い](architecture.md#住宅資料の扱い)に従ってください。
