# テスト

Vitest の Node.js 環境で、DOM から独立した計算ロジックを検証する。
テストは `tests/**/*.test.ts` に追加し、`npm test` で一括実行、`npm run test:watch` で監視実行する。

寸法・単位、姿勢、合成形状の衝突/距離、薄壁と回転途中の連続検証、固定seedの回転/傾斜探索、通信契約、applicationの中止・タイムアウト・古い応答・入力無効化を検証する。共有補間の再生位置と、テスト専用寸法・安全マージンで既知の合成経路が成立することも検証する。合成形状は `tests/fixtures/` に隔離し、UIの例・開発用選択肢・製品Workerの計算には使わない。テスト0件は失敗になる。

期待値は解析可能な寸法と手で組み立てた姿勢列から定める。seedとノード予算を固定し、時間上限は別に確認する。数値誤差テストは検証条件の回帰であり、任意の凸形状に対する誤差保証ではない。`path-clearance.test.ts`では保存姿勢間の最小値、最後の辺での全体最小、問い合わせ/時間不足時のnull、同期の距離/掃引照会が期限を越えた場合のnullを確認する。

Worker factoryと時計・タイマーのNodeテストに加え、[専用ページ](../docs/development.md#計算基盤のブラウザ検証)で仮定住宅の小箱経路・固定要求境界・20回中止/再生成を通常/Pagesサブパスで確認する。製品Workerは独立f64幾何を使い、WASM初期化はM1の比較診断で検証する。範囲外、旧シナリオ、別経路/方向/版を拒否する。`maisonette-model.test.ts`は台帳と形状・6回り段・積層床・小箱参照列、`maisonette-search.test.ts`は自動探索と床/終端/予算を検証する。仮定住宅の経路は現物の正解データではない。実測・実機タッチ・保持メモリは別ゲートとする。

`appliance-reference-path.test.ts`は探索器と独立に求めた冷蔵庫・縦型洗濯機の姿勢列の全辺を検証する。途中床のportalを除去した負例も含める。参照座標を製品探索へ読み込まず、`maisonette-search.test.ts`で入力からの発見と全辺再検証を確認する。`local-maisonette-maneuver.test.ts`はguide点からの同床内複合旋回と、共有予算・未確定接続・中止の扱いを検証する。`motion-sweep-verification.test.ts`は掃引証明・床に平行な移動・外周への途中突出・例外と予算不足の負例を確認する。

住宅v3は2階到達後に右折してから直線廊下を進む。モデル回帰で旧直進先の閉鎖、新廊下の下階壁通過、移動した上階床の跡に枠上方の余剰空間を残さないことを確認する。家電参照の全箱離脱は開口法線の投影と回転後の支持幅から独立に判定し、+X方向でも箱中心だけで成功にしない。上階壁の移動は下階の頭上干渉も変えるため、旧版の姿勢列・成功件数は再検証せず新版へ流用しない。

探索回帰では固定の土間案内点を候補生成時だけ拒否し、別位置を選ぶ分岐を確認する。開始中心が玄関枠外側面の1m手前にあり、外部開始領域からの中心後退がないことも、小箱・大型家電で検査する。始点より後方の屋外案内点を与え、固定参照・ハイブリッド・通常層が後退を拒否する分岐も確認する。採用姿勢・全辺・LDKの終端直進は実モデル照会で独立に検証する。実住宅で回転が必要な荷物を通せることの証明ではない。受信側の回帰は未知の床/物理ID、不正な始点/終点、経路補間と一致しない代表姿勢、幅1mm超のすき間区間を拒否する。

開発サーバーの `/tests/browser/design.html` は、単一の一直線の廊下を仮定寸法で再現する表示検証と、実際のAppのStrictMode再マウントに使用する。廊下は `src/dev/` 専用で、対象住宅の代用・別の計算経路・選択可能な例にはしない。通常/計算検証ビルドの入口には含めない。[画面・3D設計](../docs/design.md)と[開発ガイド](../docs/development.md#デザインのブラウザ検証)を参照する。

3D 描画・Web Worker の実通信・モバイル操作は Node.js のテストでは確認できない。[動作確認手順](../docs/verification.md#動作確認)を使用する。

性能計測ページの画面外観察は390×844のiframe内で資材要求とcanvas生成を比較する。計算中の不要描画観察は静止した製品canvasのWebGL2 draw関数を2秒間ラップし、終了時に復元する。入力・結果変更では更新し、進捗だけでは描画しないことを確認する。静的住宅形状の結合では三角形数・材質・透明描画順を保持し、描画命令/geometry数だけを比較する。[性能評価](../docs/performance.md)を参照し、実機性能・GPU時間・保持メモリと区別する。

製品の性能は`npm run build:performance` / `npm run preview:performance`の`/tests/browser/performance.html`で測定する。製品の距離判定は診断なしの独立f64を既定とし、M1/専用診断回帰だけ`diagnosticFactory`を注入する。`diagnosticsEnabled:false`と、不一致のない診断結果を区別する。診断有無で区間・状態・物理IDが変わらない比較を保持する。壁時計の速度閾値をCIの正しさテストへ入れず、[性能評価](../docs/performance.md)の同一端末・条件で初回と後続5回を比較する。RAF周期・CPU描画時間・リソース数はGPU時間/保持メモリとは別の観測である。

M1の独立した回り段fixtureは `src/dev/fixtures/turn-fixture.ts` をNode回帰と専用Worker計測入口で共有する。合成探索fixture、表示廊下、製品Workerとは別で、選択肢を追加しない。`model-geometry.test.ts` は面積・内部重複・共有辺・段高・退化を独立に照合する。`housing-geometry.test.ts` は解析距離、Rapierの微小すき間不一致、物理/人工制約の分離、床境界・持上げ・連続移動を確認する。境界を未検証で拒否することを実衝突の証明と扱わない。`m1-verification-messages.test.ts` は専用通信の不正要求・有限JSONを検証する。[専用計測手順](../docs/development.md#m1回り段worker計測)と[幾何検証資料](../docs/geometry-verification.md)を参照する。

`prism-distance.test.ts` は有限線分の平行/点退化/極小辺と、傾いた頂点対面・辺対辺・角・薄い三角柱の距離を独立した式で照合する。±15 m移動、輪郭の逆順、接触/微小すき間も含める。矛盾した距離区間を注入し、通過扱いにならないことを確認する。`rapier-diagnostic.test.ts` は実WASM資源へ照会/結果読取の例外を注入し、取得済み資源が一度ずつ解放されることを確認する。これらは任意形状の誤差上限やOS/GPUメモリ測定の代わりにはならない。専用Workerは `src/dev/fixtures/distance-probes.ts` の3固定解析ケースも自動実行する。
